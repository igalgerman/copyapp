# Fresh whole-project review — 2026-10-16

Scope: the complete Windows app, all production Go packages, phone UI and service worker, installation/update/uninstall, both website copies, build workflows, existing local commits and uncommitted work. Three independent agents started without conversation history and reviewed security, behavior/testing, and recording/release tooling. This was a source review and local Windows/browser verification, not a third-party dependency audit.

## Confirmed issues fixed

- Localhost cookies crossed port boundaries. PC control now uses an explicit header and an origin-scoped sessionStorage token; native control retains its separate launch key.
- Unpairing or replacing a phone retained the previous phone's queued clipboard/files. Revocation now clears the queue and closes old streams, including the late-subscription race.
- Failed phone unpair requests appeared successful. Failure leaves the paired UI intact; a persistence failure instead explains that disconnection is temporary and must be retried on the PC.
- A Windows sharing lock could prevent deleting a revoked session. A durable revocation marker prevents restoration after restart. A new pairing receives no cookie until persistence succeeds.
- Receive-folder aliases could bypass restrictions. Validation resolves junctions, mapped paths and short names; unsafe Downloads redirects use a validated local fallback.
- Background shortcut creation could race uninstall or an upgrade. Graceful exit and uninstall now wait for setup completion while normal startup remains asynchronous.
- The tracked website referenced missing media/release assets. Release links now pin one version; CI preserves previously published verified assets.
- Tracked-site Hebrew Windows paths and hovered selected-language buttons had readability defects. Both were corrected.

## Verification

The release process runs `build.ps1 -Version 1.0.1 -Test` (all Go tests, browser JavaScript behavior tests and vet), `docs/e2e/run.ps1 -NoBuild -LargeFiles -Browser`, and `docs/e2e/desktop.ps1` against the release executable. Recording uses that same executable with `-NoBuild`.

Integration coverage includes authenticated control/reload, real QR pairing and SSE, three languages, 390px/1280px layouts, Windows clipboard text/image round trips, file upload and browser download, destination settings, oversized transfer rejection, session/settings restart persistence, real global hotkeys and fallback, self-install, different-binary upgrade, shortcut handoff, and safe uninstall preserving unrelated files. The large-file test uploads exactly 2 GiB and compares the saved hash, validates distinct first/tail range content and Content-Range offsets, rejects oversized requests before their bodies, and verifies cancellation removes partial files. It does not download the entire 2 GiB file.

Final results: the full Go build/vet/test run, complete EXE suite with `-LargeFiles -Browser`, and native desktop suite all passed. The desktop suite also passed with `-BaselineExe landing/dist/downloads/copyapp-1.0.0.exe`, upgrading the previously published binary. The final EXE is 11,624,448 bytes; SHA-256 `055db02f221d40706dc5e4b8e49634eab50e1883fe2415e7d8a87e5c1600ddb5`.

## Verification limits

- No physical Android device was available. Android certificate installation, PWA installation, OS Share-menu integration and device-specific clipboard/download permission prompts still need testing on the target phone. Browser integration uses a test-only certificate bypass; production TLS behavior is unchanged. Illustrated OS screens in the tutorials are labeled.
- The tutorials use real app, pairing and transfer footage. Windows startup/green-confirmation scenes are clearly labeled illustrations because native window capture was unavailable; the underlying install, send and hotkey behaviors passed the separate integration tests. Public QR pixels and Wi-Fi/address/path labels use examples rather than live pairing secrets or personal paths.
- The Go race detector could not run because the environment has no C toolchain/CGO support. Concurrency regression tests and normal Go tests did run.
- Receive-folder validation cannot prevent a malicious process running as the same Windows user from changing a junction afterward; same-user malware is outside the application's trust boundary.

Release files, publication results and final verification are recorded in the GitHub v1.0.1 release and its SHA256SUMS asset.
