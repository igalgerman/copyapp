# ארבעה סרטונים מצילום אמיתי

סטטוס: הכנת ההפקה בלבד. **אין כאן סרטונים חדשים מוקלטים, ו־Issue #4 נשאר פתוח.**
צריך לקבל מבעל האפליקציה או מבודק הקלטות מסך אמיתיות של מחשב Windows וטלפון
Android פיזי, רצוי Samsung. סביבת הפיתוח אינה יכולה לצלם מכשירים אלה.

## לפני הצילום

1. התקינו את אותה גרסת Windows שאותה מפרסמים. רשמו את תג הגרסה, דגם הטלפון,
   גרסת Android, גרסת הדפדפן, מצב קבלת תמונות במחשב וקיצור המקשים הפעיל.
   בדקו את #3 במכשיר אמיתי. קיצור ברירת המחדל הוא Ctrl+Alt+C; אם נרשם קיצור
   חלופי, מציגים אותו בצילום ובכתוביות. אפשר להשתמש בכפתור השליחה הקיים בחלון
   המחשב, אבל אז מראים אותו ולא כותבים שנלחץ קיצור מקשים.
2. חברו את שני המכשירים לאותה רשת, צמדו אותם והעבירו טקסט ותמונה בשני הכיוונים.
   השאירו את דף CopyApp בטלפון פתוח בצילומי קבלה. תצוגה בטלפון אינה הוכחה
   שהתוכן הועתק ללוח; כדי להוכיח העתקה מציגים גם הדבקה.
3. הפעילו מצב ״נא לא להפריע״. השתמשו בצ'אט בדיקה ללא מספרי טלפון, שמות אישיים
   או הודעות אמיתיות. טקסט הדגמה: ״נפגשים בשש ליד הקפה״. השתמשו בתמונה אמיתית
   שצילמתם, למשל ספל על שולחן. הסתירו קודי צימוד, כתובות וקבצים אישיים בצילום.
4. צלמו ב־Windows עם OBS Studio: מקור Window Capture לחלון הרלוונטי, לכידת
   סמן מופעלת, הקלטה מקומית ללא שירות שידור. השתמשו ב־MKV והמירו ל־MP4 דרך
   File → Remux Recordings. צלמו חלון מוגדל, לא שולחן עבודה מלא עם אותיות קטנות.
   ב־Samsung השתמשו במקליט המסך המובנה ובאפשרות הצגת נגיעות אם קיימת. אם אין
   מקליט מובנה, אפשר `adb shell screenrecord /sdcard/copyapp.mp4`, לעצור ב־Ctrl+C,
   ואז `adb pull /sdcard/copyapp.mp4`. פקודות אלה דורשות חיבור USB ו־USB debugging
   שהבעלים אישר במכשיר. אין צורך ב־root. בדקו שההקלטה כוללת את תפריט השיתוף.
5. התחילו את שתי ההקלטות לפני כל ניסיון. לצורך סנכרון לחצו פעם אחת על אות
   בטקסט ההדגמה במחשב, שלחו אותה והשתמשו בהופעתה בטלפון לסימון נקודת הסנכרון.
   מדדו את זמני ההתחלה לכל קובץ בנפרד. שמרו את רצף פעולת המקור והקבלה ללא
   החלפת תוכן או חיבור בין שני ניסיונות שונים. אפשר לחתוך המתנה מחוץ לרצף.

## צילום 1 — טקסט מהמחשב לטלפון, 20–30 שניות

| זמן יעד | פעולה אמיתית | כתובית |
| --- | --- | --- |
| 0–5 | סמן טקסט ב־Notepad והעתק ב־Ctrl+C; הטלפון מוצג במקביל | במחשב: מסמנים טקסט ומעתיקים |
| 5–10 | לחץ על קיצור המקשים הפעיל, או צלם לחיצה על כפתור השליחה | לוחצים על קיצור השליחה שמופיע במחשב |
| 10–17 | הראה את כרטיס הטקסט החדש בטלפון ואת תוכנו | הטקסט הגיע לטלפון |
| 17–27 | הקש ״העתקה״ בכרטיס והדבק בשדה כתיבה ריק בטלפון | מקישים על העתקה ומדביקים במקום הרצוי |

בכתובית השנייה החליפו את התיאור בקיצור המדויק שנבדק, או בשם הכפתור המצולם.
אל תבטיחו העתקה אוטומטית אם הדפדפן מבקש לחיצה.

## צילום 2 — תמונה מהמחשב לטלפון, 20–30 שניות

| זמן יעד | פעולה אמיתית | כתובית |
| --- | --- | --- |
| 0–6 | העתק תמונה אמיתית ללוח מתוך Paint או ״העתקת תמונה״ בדפדפן | במחשב: מעתיקים תמונה |
| 6–11 | הפעל את אותה פעולת שליחה שנבדקה בצילום 1 | שולחים דרך CopyApp |
| 11–19 | הראה את התמונה החדשה בכרטיס בטלפון | התמונה הגיעה לטלפון |
| 19–29 | הקש ״שמירה״ והראה את הקובץ בהורדות, או הדבק אחרי ״העתקת התמונה״ אם נתמך | מקישים על שמירה ופותחים את התמונה |

בחרו מסלול סיום אחד שנבדק במכשיר הזה. צילום של טקסט בתוך תמונה אינו תחליף
לצילום תמונה אמיתית; אין להסיק שהורדה הצליחה רק מפני שכפתור נלחץ.

## צילום 3 — טקסט מהטלפון למחשב, 20–35 שניות

**ברירת המחדל עד ששוחרר ונבדק APK: מסלול דפדפן, בשם מפורש.**

| זמן יעד | פעולה אמיתית | כתובית |
| --- | --- | --- |
| 0–7 | בצ'אט בדיקה: לחיצה ארוכה על הודעה ובחירת ״העתקה״ | בטלפון: מעתיקים הודעה |
| 7–14 | פתח CopyApp בדפדפן/קיצור הבית והקש ״שליחת הלוח״ | מסלול הדפדפן: פותחים CopyApp ומקישים על שליחת הלוח |
| 14–22 | אשר הרשאת לוח אם מופיעה; צלם הצלחה רק אחרי אישור השרת | מאשרים גישה ללוח אם הטלפון מבקש |
| 22–32 | במחשב: Ctrl+V בחלון Notepad ריק והראה את ההודעה | במחשב: מדביקים והטקסט מופיע |

אם הקריאה ללוח חסומה, צלמו את מסלול ההדבקה הידנית שהממשק מציע ותייגו את
הסרטון ככזה. אין להסיר בקשת הרשאה בעריכה כדי להציג זרימה מהירה יותר.

לאחר ש־#2 שוחרר ונבדק על Samsung, אפשר להקליט גרסה נפרדת: העתקת הודעה →
פתיחת ההגדרות המהירות → הקשה על האריח בפועל → חלון שליחה קצר → הצלחה →
Ctrl+V במחשב. השתמשו בשם המדויק של האריח כפי שהוא מופיע ב־APK המשוחרר.
אין להציג את הזרימה הזאת על בסיס עיצוב, אמולטור או קוד שטרם נבדק.

בקוד המלווה שנכתב עבור #2, השם המתוכנן כעת הוא `CopyApp: Send to PC`.
החלון הקצר מציג `Sending clipboard to PC…`, ואחריו הודעת `Sent to PC`;
כישלון מציג `CopyApp could not send` עם Retry/Close. אלה פרטי קוד לצורך
הכנת הצילום בלבד, אינם הוכחה לשחרור או לבדיקה פיזית. המסלול בוחר במפורש
בלוח של Windows; יש לאמת הדבקה בפועל גם אם הגדרת הקבלה הרגילה היא תיקייה.

## צילום 4 — תמונה מהטלפון למחשב, 20–35 שניות

| זמן יעד | פעולה אמיתית | כתובית |
| --- | --- | --- |
| 0–7 | פתח תמונת בדיקה בגלריה/WhatsApp ובחר ״שיתוף״ | בטלפון: פותחים תמונה ובוחרים שיתוף |
| 7–16 | בחר CopyApp בתפריט השיתוף והקש ״שליחה״ בתצוגה המקדימה | בוחרים CopyApp ומאשרים שליחה |
| 16–24 | הראה את אישור הקבלה ואת היעד שהשרת דיווח | התמונה הגיעה למחשב |
| 24–34 | יעד ״לוח״: הדבק ב־Paint; יעד ״תיקייה״: פתח את הקובץ מתיקיית הקבלה | מדביקים ב־Paint / פותחים מהתיקייה |

אם CopyApp לא מותקן כיעד שיתוף, צלמו מסלול עצמאי חלופי: פתח CopyApp →
״תמונה״ → בחר תמונה → שלח → הראה אותה במחשב. יש לצלם את הבחירה והאישור
שהמכשיר מציג בפועל. אריח לוח הטקסט אינו מסלול מוכח לתמונות.

## עריכה מקומית וכתוביות

העתיקו את `real-capture.example.json` לתיקייה פרטית, למשל
`C:\CopyAppRecordings\windows-text.json`. לא מוסיפים הקלטות גולמיות ל־Git.
מלאו נתוני מכשירים וגרסה, נתיבים, זמן התחלה בכל מקור, משך וכתוביות שנבדקו.
`confirmed_real_capture` נשאר `false` בדוגמה: משנים אותו רק אחרי צפייה בשני
המקורות ואימות שמדובר במכשירים פיזיים ובאותה העברה. אין להשתמש בו לאישור טסט.

```powershell
python docs/video/assemble-real.py C:\CopyAppRecordings\windows-text.json --dry-run
python docs/video/assemble-real.py C:\CopyAppRecordings\windows-text.json
```

נדרשים Python 3, ‏FFmpeg ו־ffprobe ב־PATH; בניית FFmpeg חייבת לכלול libass
לכתוביות עבריות ו־libx264. הגופן ברירת המחדל הוא Arial; ודאו שהוא מותקן
וכי אין ריבועים במקום אותיות. הכתוביות הן UTF-8 ומעובדות ב־libass עם כיווניות
עברית. כשמוסיפים קיצור באנגלית לכתובית, עטפו אותו בתווי LRI/PDI
(`\u2066` ו־`\u2069` במחרוזת JSON), לדוגמה `\u2066Ctrl+Alt+C\u2069`. יש לצפות בתוצאה
ולוודא סדר מילים ומקשים בפועל, במיוחד בגרסאות שונות של libass.

הכלי מייצא וידאו אנכי 1080×1920: חלון המחשב בחלק העליון, הטלפון מתחתיו,
וכתוביות גדולות בתחתית. שני המקורות נשארים גלויים. הוא אינו מזייף מסך, הצלחה,
נגיעה או תוכן. השתמשו ב־`crop` כדי להציג במחשב רק את החלון הדרוש; צלמו שוב
אם הפעולה אינה קריאה. אפשר להפעיל את כלי העריכה לכל אחד מארבעת קובצי ה־JSON.
ייצוא: H.264, ‏yuv420p, ‏AAC שקט, 30fps ו־faststart. הקובץ מסתיים אם אחד המקורות
קצר מהמשך שהוגדר; בדיקת הפלט מסרבת לקבל משך חסר. אין השהיה או שכפול של תוצאת
קבלה כדי להסתיר מקור קצר.

## בדיקה ופרסום — רק כשהקלטות אמיתיות מוכנות

- צפו בכל קליפ בלי קול במסך טלפון. כל לחיצה, התוכן המועבר וההדבקה/פתיחה
  צריכים להיות קריאים. בחרו 15–40 שניות לכל קליפ; שמרו התקנה בנפרד.
- שלחו כל MP4 כווידאו ב־WhatsApp למכשיר הבדיקה. בדקו השמעה מלאה, כתוביות
  אחרי דחיסת WhatsApp, ותצוגה בדפדפן Windows. אם הכתב קטן, הגדילו את חלון
  המקור או צלמו שוב; אל תסמנו את הבדיקה כעוברת לפי ffprobe בלבד.
- שמרו לצד המקורות דוח קצר: גרסה, מכשירים, קיצור פעיל, מסלול PWA/אריח, יעד
  תמונה, בדיקת WhatsApp ותאריך. ודאו שהגרסה המשוחררת כוללת בדיוק את ה־UX שצולם.
- העלו דרך דף ה־Release של **הגרסה שצולמה**, לא כקבצים במאגר:
  `windows-text.mp4`, `windows-image.mp4`, `android-text-pwa.mp4` (או
  `android-text-tile.mp4` אחרי בדיקה), `android-image.mp4`.
  אפשר להשתמש ב־`gh release upload <tag> <file1> <file2> <file3> <file4>`
  אחרי כניסה לחשבון הנכון. אל תוסיפו `--clobber`; אל תדרסו סרטונים קיימים.
- פתחו בפועל כל קישור `https://github.com/igalgerman/copyapp/releases/download/<tag>/<filename>`.
  רק אז הוסיפו קישורים בולטים ב־`site/` וב־`README.he.md` עם שמות ארבע הפעולות.
  קישורי `install.mp4` ו־`use.mp4` הקיימים נשארים זמינים עם תווית הגרסה שלהם:
  README בעברית מקשר ל־v1.0.1; האתר מקשר ל־v1.0.2. אין להציג אותם כהדגמת
  האריח החדש בלי לבדוק את הסרטון עצמו.
- #4 נשאר פתוח עד שיש ארבעה סרטונים אמיתיים, קישורים שנבדקו ובדיקת WhatsApp.
  תסריטים, כלי ההרכבה וסטוריבורד אינם ממלאים את תנאי הסיום.
